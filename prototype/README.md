# Играбельный HTML-прототип «Эхо-Цитадель»

Односторонний прототип всей игры в браузере. Нужен, чтобы **до переноса в Unity**
проверить ощущение от правил руками, показать игру заказчику без установки Unity
и зафиксировать UX-решения (ТЗ раздел 4).

## Запуск

```bash
npm run build:proto     # esbuild: src/ui/prototype.ts → prototype/prototype.js (+ копия prototype.css)
npm run proto           # статический сервер на 0.0.0.0:5173
# → http://localhost:5173/
```

Можно открыть и просто `prototype/index.html` файлом — весь код и данные инлайнятся
в один бандл (`Cards.json` и `Decks.json` включены в сборку), внешних запросов нет.

## Headless-проверка

```bash
npm run smoke           # jsdom: 12 ходов, розыгрыш карт, Эхо, конец игры
```

Тест гоняет прототип в jsdom и проверяет **36 утверждений**: меню, коллекцию из 150 карт,
фильтры, экран правил, муллиган, соответствие DOM и состояния движка, розыгрыш карт
кликом, работу Эха, наполнение лога, экран конца игры, перезапуск и возврат в меню,
а также блок «визуальный слой»: 4 параллакс-слоя, поверхность стола, пост-слои,
VFX-слой и SVG-фильтры, классы редкости и слои `innerframe/spec/foil` у карт,
наличие мотива в арте, портреты героев, 3D-тилт при наведении, тумблер звука.
Последний прогон: **все проверки зелёные, 0 ошибок на странице.**
(Две «ошибки» jsdom про `HTMLCanvasElement.getContext` — ограничение тестовой среды:
в jsdom нет 2D-канваса без пакета `canvas`; в браузере ambient-частицы работают.)

## Управление

| Действие | Как |
|---|---|
| Разыграть карту | **Перетащить** на поле (существа/руны) или на цель (заклинания) — допустимые цели подсвечиваются золотом |
| То же без перетаскивания | **Клик** по карте; если нужна цель — клик по подсвеченному существу/герою, `Esc` — отмена |
| Завершить ход | Кнопка или **Пробел** |
| Эхо-очко | Кнопка «◈ Эхо» или **E** |
| Пересдача | Один раз в начале игры: кликом отметить карты «ЗАМЕНИТЬ» |
| Коллекция / правила | Кнопки в меню |

Недоступные для розыгрыша карты в руке показаны приглушёнными; при наведении
всплывает подсказка с полным текстом, типом, редкостью и flavor-текстом.

## Что реализовано по ТЗ

- **п.2.1** колода минимум 60 карт (без верхнего лимита), до 4 копий любой карты включая легендарные, без сайдборда; 30 HP, стартовая рука 5, муллиган 1 раз, усталость при пустой колоде;
- **п.2.2** пять фаз хода с индикатором-треком и баннером фазы; фаза «Битва» автоматическая,
  с пошаговой анимацией каждой атаки (полёт → удар → числа урона → смерть);
- **п.2.3** мана 1→10, полное восполнение в фазу «Ресурсы»;
- **п.2.4** руны (не более 3, копии запрещены, не уничтожаются обычными заклинаниями) и ритуалы
  (отложенное разрешение в начале следующего хода);
- **п.2.5** пассивки пяти фракций в редакции v2 (`docs/ADDENDUM_passives.md`);
- **п.2.6** Эхо-очки: начисляются, если за основную фазу не разыграно ни одного заклинания,
  тратятся один раз за игру на бесплатное повторение последнего заклинания;
- **п.4.1** три зоны экрана: верх (герой противника + его руны + войска), центр (ваше поле),
  низ (ваш герой, руны, рука, панель действий, лог);
- **п.4.2** рука веером с подъёмом и поворотом, наведение увеличивает карту, drag&drop;
- **п.4.4** индикатор фазы и текущего хода;
- **п.4.5** прокручиваемый лог событий с цветовой разметкой (ваш ход / ход противника / урон / система);
- **п.5** ИИ-противник: приоритеты ТЗ п.5.2 (летал → выживание → размен → развитие),
  фракционный стиль (aggression/selfPreservation из `AI_PROFILES`), «неидеальность»
  через `blunderRate` (три уровня сложности в меню), пауза 1–2 с на ход;
- **п.6.2** анимации: выход существа, атака, тряска при получении урона, всплывающие числа,
  растворение при смерти, вспышка героя при заклинании, свечение рун, «голограмма» на карте.

## Визуальный слой (реализован)

Прототип повторяет визуальный стек Unity-порта средствами CSS/SVG/Canvas —
см. `docs/VISUAL_STACK.md`. Модули:

| Файл | Что делает | Аналог в Unity |
|---|---|---|
| `src/ui/vfx.ts` | тряска экрана с направлением и затуханием, hit-stop, кольца удара, искры, слэши, столпы света, наземные декали в перспективе, рябь, дым, полёт «души» по дуге, снаряды с трейлом, тепловое марево (`feTurbulence`+`feDisplacementMap`), растворение, глитч/хромаберрация, Canvas-ambient (70 частиц), параллакс, пост-слои (виньетка/грейн/грейдинг) | CameraRig + DOTween, VFX Graph, Decal Projector, URP Volume |
| `src/ui/audio.ts` | 21 звук, синтезированный WebAudio — без единого файла; стихии заклинаний звучат по-разному, щит = стеклянный пинг, Эхо = призвук с задержкой; тумблер в верхней панели | список клипов для AudioSource |
| `src/ui/art.ts` | процедурный арт: 17 тематических мотивов, выбор по тегам → ключевикам → стихии; атмосфера (небо, лучи, туман, искры фракции, силуэт земли), rim-light и контур «тушью»; портреты героев; 4 слоя фона; каменная поверхность стола | `Resources/Cards/<id>.png` по полю `art` в `Cards.json` |
| `src/ui/prototype.css` | надстройка поверх базовых стилей: материал карты (внутренняя золочёная рамка с уголками, блик за курсором, **фойл по редкости**), состояния существ (щит-купол, ледяная корка, призрачное мерцание неуловимости, каменная окантовка Провокации, тень-пятно), «низкое HP» героя, пульс целей, sheen на кнопках | All In 1 Sprite Shader, True Shadow |

Карта под курсором наклоняется в 3D (`rotateX/rotateY` от позиции мыши), а
спекулярный блик ездит за курсором — это CSS-эквивалент specular highlight из
All In 1 Sprite Shader. Уважается `prefers-reduced-motion`: вся анимация отключается.

Базовые стили намеренно оставлены инлайном в `index.html`, а визуальный слой
подключается внешним `prototype.css` — поэтому прототип открывается и по `file://`
(без визуального слоя), и с сервера (полная картина).

## Что сделано заглушкой (сознательно)

- **Арты.** Вместо PNG 512×720 — процедурный SVG из `src/ui/art.ts` (детерминированный
  от id карты, поэтому все 150 карт выглядят по-разному). Путь к будущему арту уже лежит
  в `Cards.json` (`art` / `artworkPath` = `Resources/Cards/<id>.png`), так что замена
  в Unity — это просто загрузка текстуры по этому пути.
- **Звук** — синтезируется в браузере (`src/ui/audio.ts`); в ТЗ звук не заявлен, поэтому
  это необязательное расширение с тумблером. Финальные клипы для Unity — отдельная задача.
- **Колоды** — 6 готовых (5 фракционных + нейтральная); конструктора колод в прототипе нет.

## Соответствие кода прототипа и будущего порта в Unity

Прототип намеренно не содержит собственной игровой логики: он **вызывает тот же движок**,
который портируется в C#. Соответствие один-в-один:

| Прототип (TypeScript) | Unity (C#), целевой скрипт |
|---|---|
| `src/engine/types.ts` | `Assets/Scripts/Core/GameTypes.cs` |
| `src/engine/engine.ts` → `GameEngine` | `Assets/Scripts/Core/GameEngine.cs` |
| `src/engine/ai.ts` → `AIController`, `AI_PROFILES` | `Assets/Scripts/AI/AIController.cs`, `AIProfiles.cs` |
| `src/engine/db.ts` → `buildDatabase` | `Assets/Scripts/Data/CardDatabase.cs` (загрузка `StreamingAssets/Cards.json`) |
| `src/ui/prototype.ts` → `Battle` | `Assets/Scripts/UI/BattleController.cs` |
| `Battle.renderHand` (веер) | `HandView.cs` + DOTween (`DOFan`) |
| `Battle.animateCombat` (очередь атак) | `CombatPresenter.cs`, читает `GameEngine.AttackQueue` |
| `Battle.onEvent` (лог/числа/смерти) | `GameEventRouter.cs` → `LogView`, `FloatingText`, `DeathFx` |
| `src/ui/art.ts` (процедурная заглушка) | `CardArtLoader.cs` → `Resources/Cards/<id>.png` |
| `src/ui/vfx.ts` | `Visuals/VfxCatalog.cs` + префабы из `docs/VISUAL_STACK.md`, раздел 6 |
| `src/ui/audio.ts` | `Visuals/AudioCatalog.cs` + клипы AudioSource |
| `src/ui/prototype.css` | материалы URP: All In 1 Sprite Shader + True Shadow |

Ключевое архитектурное решение, которое переносится в Unity как есть:
**движок синхронный и детерминированный, а представление — асинхронное.**
Фаза «Битва» просчитывается движком целиком и складывает план атак в `attackQueue`
(с состоянием атакующего и защитника *до* удара); UI затем проигрывает этот план
по одной атаке. В Unity это превращается в корутину/DOTween-последовательность поверх
уже готового `AttackQueue`, без единой строчки игровой логики в слое представления.
