# Модель баланса «Эхо-Цитадель»

Как устроены сила карты, вывод её стоимости, подбор коэффициентов фракций
и метрики приёмочного автотестера (ТЗ п.8.1, п.10.8).

---

## 1. Сила карты (power)

Каждая карта сводится к одному числу — «очкам баланса». Для существ это сумма
тела и способностей, для заклинаний и рун — сумма эффектов с поправкой на тип.

### 1.1 Существо

```
power = bodyMul × (attack + health × k_hp)
      + Σ keywords_power
      + Σ onTurnStart_power × turns_expected
      + aura_power
```

- `k_hp = 1.0` — здоровье и атака считаются равноценными (в авто-бою размен обоюдный);
- `keywords_power`: Провокация 1.0, Вампиризм 1.4, Рывок 1.2, Буря 1.6, Прорыв 1.3,
  Неуловимость 1.5, Урон заклинаний +1 → 1.2, Предсмертный хрип = сила его эффекта;
- `turns_expected` — сколько ходов в среднем проживёт триггер начала хода
  (берётся 3 для партии в 12.3 хода с учётом вероятности смерти);
- `aura_power` — аура существа: `value × число затрагиваемых целей × 0.8`.

### 1.2 Заклинание

```
power = spellMul × Σ effect_power × target_factor × repeat_factor
```

- `target_factor`: одна цель 1.0, все существа противника 2.2, все существа 2.8,
  «случайная цель» 0.8, герой 0.9;
- `repeat_factor` = `1 + 0.35 × (повторы − 1)`;
- **Ритуал** (`ritualDelay ≥ 1`) получает множитель **1.35** — задержка компенсируется силой.

### 1.3 Руна

```
power = runeMul × (aura_power × rune_turns + trigger_power × turns_expected)
```

Руна считается на весь ожидаемый срок жизни: постоянная (`turnsLeft = -1`) —
на `min(6, оставшаяся длина партии)`. Это консервативная оценка: как показала
практика (см. раздел 6), для 7-мановых рун она всё ещё занижена.

### 1.4 Стоимость эффекта (`effect_power`)

Базовые цены в «очках баланса»:

| Операция | Цена за единицу |
|---|---|
| `damage` (существо/герой) | 1.00 за 1 урон |
| `heal` | 0.55 за 1 HP |
| `draw` | 2.60 за карту |
| `buff` (+X/+Y) | 1.00 за пункт |
| `applyStatus: Burn` | 1.20 за тик (+35% за каждый следующий) |
| `applyStatus: Poison` | 2.40 |
| `applyStatus: Freeze` | 1.80 за ход |
| `applyStatus: Shield` | 1.30 за заряд |
| `applyStatus: Silence` | 2.20 |
| `destroyCreature` | 5.00 |
| `returnToHand` | 2.80 |
| `summonToken` | power токена |
| `extraMana` (руна) | 3.20 за 1 ману |
| `extraDraw` (руна, за ход) | 2.60 |
| `heroProtection` (руна) | 2.20 за 1 снижение |
| `spellDamage` (руна) | 2.00 за +1 |
| `healReduction` «Выжигание» | 1.60 за 1 |

## 2. Вывод стоимости из силы

```
cost = clamp(round((power − 1.2) / 2.0), 1, 10)
```

Дальше карту **подгоняют под полученную стоимость** (`fit_to_cost`), а не наоборот:
если дизайнерское тело не соответствует цене, корректируются статы в пределах
жёстких ограничений.

### 2.1 Ограничения (защита от вырожденных карт)

| Ограничение | Значение | Почему |
|---|---|---|
| Пол здоровья | `health ≥ cost + 1` | В авто-бою цель выбирается по **наименьшему здоровью**: существо с меньшим телом умирает, ни разу не атаковав |
| Потолок атаки | `attack ≤ cost + 3` | Иначе авто-балансировщик порождает «стеклянные пушки», ломающие размен |
| Потолок здоровья | `health ≤ cost + 6` | То же, с другой стороны |
| Ауры по стоимости | `AURA_MAX_BY_COST` | Аура за 2 маны не может давать +4/+4 |
| Длительность статусов | `STATUS_DURATION_CAP` | Заморозка на 12 ходов недопустима |
| Неизменяемые эффекты | «пол» стоимости | Карта с `destroyCreature` не может стоить 1 ману, как бы ни было мало тело |
| Число рун | ≤ 3, копия запрещена | Ограничение движка (ТЗ п.2.4.3) |
| Неуловимость | ≤ 3 существ на фракцию | В авто-бою это бесплатный урон в героя без ответа |

### 2.2 Редкости

Распределение фиксируется ровно под ТЗ п.3.2 (60/25/10/5 % → 90/38/15/7 карт)
функцией `fix_rarities`: редкость назначается по силе карты внутри фракции,
а не вручную.

## 3. Коэффициенты фракций

Четыре множителя на фракцию (`tools/generator/faction_balance.json`):

| Коэффициент | На что влияет |
|---|---|
| `bodyMul` | статы существ (атака/здоровье) |
| `spellMul` | сила эффектов заклинаний |
| `runeMul` | сила эффектов рун |
| `passiveMul` | сила пассивки **в движке** (см. раздел 5) |

Первые три применяются **на этапе генерации** (меняют сами карты и их стоимость),
`passiveMul` — **в рантайме** (меняет вероятность/величину срабатывания пассивки).

### 3.1 Вероятностное округление `pround()`

Движок дискретный, а коэффициенты дробные. Наивное `Math.round` давал
осцилляцию: при `passiveMul = 0.5` пассивка то включалась целиком (винрейт 80%),
то выключалась (40%), и решатель не сходился.

`pround(x)` возвращает `floor(x)` с вероятностью `x − floor(x)` и `ceil(x)` иначе,
используя ГСЧ партии. Матожидание равно `x`, поэтому **в среднем по 10 000 матчей**
сила пассивки соответствует коэффициенту, а отдельная партия остаётся «честной»
и детерминированной относительно сида.

## 4. Решатель коэффициентов

`tools/balance/solve_balance.ts` — итерационный подбор обратной связью:

1. Прогон матрицы матч-апов 5×5 (каждая пара фракций, обе стороны) по `--per-pair` матчей.
2. Для каждой фракции: если винрейт > 55% — коэффициенты уменьшаются, < 45% — увеличиваются.
   Шаг пропорционален отклонению (`--gain`, по умолчанию 0.6).
3. **EMA-сглаживание** (`--ema` 0.6) по винрейтам, чтобы не гоняться за шумом выборки.
4. `bodyMul = spellMul = runeMul` меняются вместе (единый «уровень силы» фракции);
   `passiveMul` — отдельно, т.к. влияет на другую ось.
5. Коэффициенты пишутся в `faction_balance.json`, карты **перегенерируются**,
   цикл повторяется.
6. Остановка: все фракции в коридоре по EMA **и** отклонение каждой < 0.06 **и**
   сделано ≥ 14 раундов (защита от преждевременной сходимости на одном удачном прогоне).
7. Финальный контрольный прогон `--final-per-pair` матчей на пару.

### 4.1 Что решатель НЕ может починить

Коэффициенты двигают «уровень силы» фракции, но не её **структуру**. Замеренный пример:
Пироманты упирались в пол ~43.5% при любых коэффициентах, потому что переуронили
противника (37.4 урона за игру против 28.3 у Некрусов) и всё равно проигрывали гонку
сустейну Некрусов (24.3 лечения за игру). Потребовались изменения дизайна:
новое свойство «Выжигание» (`healReduction`), отмена самоурона у «Ифрита»,
сокращение числа неуловимых существ у Эфирных. **Вывод:** структурную проблему
надо решать картами, а не коэффициентами.

## 5. Пассивки как объект балансировки

Редакция ТЗ п.2.5 v2 (`docs/ADDENDUM_passives.md`) задаёт **механику и знак** пассивки,
а `passiveMul` — её точную силу. Текущие значения:

| Фракция | passiveMul | Эффект в игре |
|---|---|---|
| Ауриты | 0.4744 | щит срабатывает ~в 47% выходов существа стоимостью ≥2 |
| Некрусы | 1.4003 | «Кровавая жатва» даёт ~2.8 HP (2 × 1.4) и карту |
| Терраморфы | 1.3698 | рампа ~+1.37 маны/ход; «мирные» 3 хода соблюдаются всегда |
| Пироманты | 1.8235 | +1.8 урона дешёвым заклинаниям, +3.6 дорогим; плата −1.8 HP |
| Эфирные | 0.5585 | шанс неуловимости ≈56% |

Такая схема позволяет сохранить читаемые формулировки в ТЗ и при этом
довести винрейты до коридора автоматически.

## 6. Метрики автотестера

### 6.1 Фракции (ТЗ п.10.8)

Винрейт по всем матчам фракции во всех матч-апах, обе стороны. Критерий приёмки:
**45–55%**. Дополнительно пишутся средняя длина партии, урон, лечение, число
сыгранных карт и использований Эха — по ним видно **стиль** фракции
(Пироманты: 8.3 хода и 31.7 урона; Ауриты: 15.9 хода и 13.5 лечения).

### 6.2 Карты: маргинальный вклад вместо «винрейта карты»

Формула ТЗ п.8.1 («винрейт карты = победы / (победы + поражения) при её наличии в колоде»)
**неинформативна**: карта попадает в колоду победителя по построению, а нейтральные
карты лежат в обеих колодах. Замеры давали абсурд: нейтральные карты «75%»,
«Ледяной ветер» — 0 розыгрышей и 4197 «побед».

Заменено на **маргинальный вклад**:

```
RelativeWinRate = P(победа | карта была разыграна) − P(победа | играет её фракция)
```

- `0` — карта ровно среднего уровня своей фракции;
- `> 0` — с ней выигрывают чаще, чем в среднем по фракции;
- флаг `NeedsBalance` при `|вклад| > 5 п.п.` **и** ≥ 100 розыгрышах
  (иначе это шум малой выборки).

Это adaptation, а не нарушение ТЗ: цель пункта («найти карты, ломающие баланс»)
достигается, а буквально указанная формула для этого непригодна. Отклонение
зафиксировано в `docs/ADDENDUM_passives.md`.

### 6.3 Диагностика

`tools/balance/duel.ts` гоняет одну пару фракций с трассировкой: число атак за игру,
урон по герою, лечение, добór. Именно он показал корень исходного дисбаланса —
Ауриты делали 24.5 атаки за игру, Некрусы 5.1, потому что их «стеклянные» тела
умирали до первой атаки (см. ограничение «пол здоровья» в разделе 2.1).

## 7. Воспроизведение

```bash
# карты (пишет Cards.json, Decks.json, art_prompts.csv, card_power_report.csv)
python3 tools/generator/generate_cards.py

# решатель коэффициентов
npx esbuild tools/balance/solve_balance.ts --bundle --platform=node --outfile=build/solve_balance.js
node build/solve_balance.js --rounds 45 --per-pair 56 --final-per-pair 140

# приёмочный автотестер (ТЗ п.8.1)
npx esbuild tools/balance/run_balance.ts --bundle --platform=node --outfile=build/run_balance.js
node build/run_balance.js --matches 10000 --seed 20260903
```

Отчёты попадают в `docs/balance/`: `balance_report.csv` (по фракциям и матч-апам),
`faction_report.csv`, `card_power_report.csv`, `summary.md`, `solver_result.json`.

Прогон 10 000 матчей занимает ~4.5 с, поэтому решатель успевает сделать
несколько десятков раундов за минуту — это и делает автобалансировку практически применимой.
