# Эхо-Цитадель — этап расширения (концепт v1, 2026-09-04)

Статус: **переходим на этап расширения**. Текущие 5 колод фракций из Decks.json помечены
в интерфейсе как **базовые** («· база (60)»). Движок, стадии и визуал Arena сохраняются;
исторический прогон баланса на 10 000 матчей был выполнен до перехода на 60-карточные колоды
и требует повторной оценки для новых преконструктов.

## 1. Герои и колоды как в MTG
- Герой фракции = аватар художника из `art_raw/heroes/<Фракция>/` (уже подтягивается в меню,
  медальоны боя, фолбэк-сигил). Маршрут `/heroes/<Faction>` ищет оба корня drop-зоны
  (`echo-citadel/art_raw/heroes` и `/home/user/art_raw/heroes`).
- Следующий шаг (v2): герой получает карточку-командира (имя, титул, способность-эмблема),
  колоды строятся вокруг героя (формат, близкий к Commander): герой задаёт фракцию-идентичность,
  дек-лист привязывается к герою, в бою медальон = портрет героя + его эмблема в углу.
- Конструирование: только карты из владения (см. п.2), минимум 60 карт, без верхнего лимита; до 4 копий любой карты (включая легендарные), без сайдборда.

## 2. Владение и бустеры (v1 — реализовано)
- Хранилище владения: localStorage `ec_owned_v1` ({id: count}); базовый набор 150 карт
  считается полученным (×1). Дубликаты копятся счётчиком.
  **Обновление:** с этапа v1.6 ключ — `ec_owned_v2`; при первом запуске содержимое
  `ec_owned_v1` автоматически мигрирует в `ec_owned_v2` (см. `ownedLoad`).
- Бустер «Эхо-Цитадель»: 5 карт, шансы редкостей по ТЗ п.6: **обычная 60% / редкая 25% /
  эпическая 10% / легендарная 5%** (PACK_ODDS). Кнопка «◈ Бустеры» в меню, модалка с рубашками
  и переворотом по клику (rotateY, preserve-3d).
- Коллекция: бейдж «×N» на картах с дубликатами; конструктор колод в v2 фильтрует пул по владению.

## 3. Дорожная карта
1. **v1 (готово):** владение, бустер 5 карт, базовые колоды с меткой, бейджи копий.
2. **v2:** карточки героев-командиров + привязка дек-листов; фильтр конструктора по владению;
   pity-механика бустеров (гарантия эпика раз в N паков, легендарки — раз в M).
3. **v3:** наборы расширения (сет-код, новые карты поверх 150), ограниченная ротация форматов
   (база / расширение / командир), витрина набора в меню.
4. **v4:** экономика (валюта/задания) и драфт-режим бустеров (3 пака, пики 1-1-1 против ИИ).

## 4. Ограничения v1 (осознанно)
- Бустеры бесплатны (демо-режим): экономика появится в v4.
- Владение не ограничивает базовые колоды (они собраны из базового набора полностью).
- Аватары героев по-прежнему целиком за художником: генератор ничего не рисует сам.

## 5. Реализовано в v1.5 (2026-09-21)
- **Покупка бустеров**: валюта «осколки эха» ◈ (старт 1200), цена бустера 300 ◈, кнопка
  «Купить бустер» в модалке; баланс виден в меню (пилюля ◈).
- **Playset 4**: максимум 4 копии карты во владении; 5+ копия конвертируется в осколки
  (20/40/80/150 по редкости). В конструкторе колод MAX_COPIES = 4 (MTG playset).
- **Состав бустера как в MTG**: 3 обычных + 1 редкая + 1 эпическая (1/8 легендарная);
  фойл-слот 1/5 (✦-бейдж, холодное свечение рамки); дубликаты и фойл-избышек → ◈.
- **300 карт**: Расширение I (+144: 70 существ, 45 заклинаний, 25 рун; 62 мгновенных,
  26 масс-зачисток). Генератор tools/generator/expand_300.py (клон-донор + бюджетная
  модель). Баланс: 10 000 матчей базы — коридор 47.5–51.8%; прогон смешанных колод
  (база+новые): 0 карт с вкладом >5 п.п.
- **Мгновенные заклинания и стадии**: SpellSubtype.Instant играется в свою Main/Combat/End
  и в **окна отклика** на ходе противника (MTG-приоритет): док-панель «⚡ Окно отклика»
  с кнопкой «Передать приоритет» (авто-пас 20 c); события InstantWindow/Closed; ИИ отвечает
  мгновенными эвристикой (перед вашей атакой и в конец хода). Масс-зачистки по этапам:
  damageAllCreatures / burnAllEnemies / damageAllEnemyCreatures (сорсери Epic+).
- **Арты под карту**: object-fit:cover + object-position 50% 38% для всех карточных
  изображений — любые пропорции файлов художника кадрируются без искажений.

## 6. v1.6 — прогрессия открытия коллекции (2026-09-21)
- На старте открыта ТОЛЬКО база: 150 карт фракций + нейтральные (×1), ключ владения ec_owned_v2.
- Карты Расширения I (144, id *_31..44 / *_s10..18 / *_r07..11) на старте ×0: в коллекции
  показываются замком (grayscale + бейдж «◈ из бустера»), фильтр «только полученные».
- Бустер = набор ECH1: пул дропа содержит ТОЛЬКО карты расширения; база из бустеров не падает.
- Гейты: конструктор — пул и сохранение только по полученным копиям (≤4 и ≤ владения);
  старт боя — колода с неполученными картами расширения не запускается (журнал + «Колода недоступна»).

## 10. v2.2 — движок и продакшн-ревью (событийность, данные, доступность, запуск)

Ответ на ревью «rules-engine/event-driven». Все гейты сохранены: смоук 🎉, tsc clean,
аудит способностей 35/35, баланс-сим 10k: фракции 47.8–53.6% (коридор ТЗ 45–55%).

- **LIFO-стек инстантов (event-driven)**: движок — pub/sub (`emit`/`hooks.onEvent`, журнал
  4000 событий); мгновенные заклинания теперь реально кладутся в стек: события
  `StackPushed`/`StackResolved`, `engine.stack[]`, `resolveStackTop()` (LIFO: последний
  вошёл — первый разрешился), `passStack()`. Окна ответа чередуются: AI отвечает своими
  инстантами автоматически, игрок получает окно «Ответить/Пас» (принудительный пас при
  пустой руке). `interactiveStack=false` в симах/аудите ⇒ push+мгновенный резолв ⇒
  **паритет симуляций гарантирован** (баланс и аудит не изменились). В бою UI ставит
  `interactiveStack=true`, панель #stackPanel рисуется из engine.stack, ▶ — вершина.
- **Слои эффектов (effect layers)**: перманентные модификаторы не «впекаются» в базовые
  статы — они живут отдельными типизированными статусами на существе (`statuses[]`:
  Shield поглощает урон, Silence снимает всё, баффы/дебаффы стакаются по типу с
  обновлением значения), поэтому порядок наложения не ломает итог (аналог layer-safe
  модели MTG); временные эффекты имеют срок и снимаются на апкипе.
- **PostgreSQL, нормализация** (server/schema.sql): `profiles.password_hash`,
  `decks.is_active`, `match_history.duration_seconds`, таблица `deck_cards`
  (deck_id, card_id, count 1–4 — вместо jsonb), телеметрия `match_card_events`
  (played/stuck по ходам) и вью `v_card_winrate` (winrate при розыгрыше, ср. длина)
  для Metabase/Grafana.
- **Телеметрия и data science**: клиент пишет каждый живой матч в `meta.telem`
  (фракция, win, ходы, секунды, played:[cardId,turn] ≤60, stuck:рука на конец, кап 40);
  раздел «Телеметрия» в модалке профиля (средняя длина, топ застревающих карт).
  `tools/autonerf.py` → docs/balance/nerf_proposals.md (нерж 30 / бафф 10 кандидатов
  по WinRateWhenPlayed вне 45–55% с NeedsBalance=YES; **без авто-применения**,
  `--apply` правит только cost и требует ре-сим). `tools/make_dashboard.py` →
  docs/balance/dashboard.md (CSV-дашборд + инструкции Grafana/Metabase поверх PG-вью).
  npm: `balance`, `autonerf`, `dashboard`.
- **Доступность**: режим дальтонизма (иконки фракций ✦☠⛰♨☾ на картах и юнитах +
  уникальные узоры рамок: полосы 0°/45°/90°/135° и кольца вместо опоры на цвет,
  body[data-cb]); масштаб шрифта 0.9–1.3 (html font-size через --fs, все rem-тексты);
  субтитры звуков (#subsLine, aria-live: удар/заклинание/смерть/призыв/урон герою);
  язык ru/en — UI по data-i18n + имена/тексты/флейворы карт из /locale/*.json
  (en.json заполнен: 1510/1533, пустые = 16 карт без abilityText + 7 токен-флейворов),
  маршрут /locale в serve.js. Переключатель в «Настройках» перерисовывает коллекцию,
  модалку карты, муллиган и руку. Сборка: `npm run locale`.
- **План запуска**: docs/LAUNCH_PLAN.md — альфа 50–100 (пороги: краш<2%, stuck<60%,
  NPS≥30) → региональный soft launch RU/BY/KZ (retention D1≥35%/D7≥15%/D30≥6%,
  стоп-пороги) → devlog/Next Fest/инфлюенсеры → Steam (wishlist 7k+, лутбокс-шансы
  раскрыты, 12+); чек-лист готовности с отметками что уже сделано.
