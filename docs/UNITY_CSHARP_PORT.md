# Блок 2 — порт движка на C# (Unity 2022.3 LTS)

Статус: **в работе**. Цель — 1-в-1 порт `src/engine/*.ts` на C#, чтобы одна и та же
база карт, тот же ГПСЧ и те же правила давали идентичные партии в HTML-прототипе и
в Unity. Проверка — не «на глаз», а компилятором и сверкой с эталоном, снятым с TS.

## Как проверять

```bash
npm run build:cs    # только сборка ядра (быстро)
npm run verify:cs   # сборка + 82 сверки с эталоном TypeScript
```

Стенд `tools/csharp/EchoCitadel.Tools.csproj` собирает **только чистое ядро**
(`Core/`, `Data/`, `AI/`) как консольное приложение .NET 8 и компилирует файлы
прямо из дерева Unity-проекта — дублей исходников нет. Unity-специфичные скрипты
(`UI/`, `Visuals/`, `Factions/`, MonoBehaviour, DOTween) проверяет компилятор Unity.

Эталон для сверки — `tools/csharp/expected.json`: его снимает сам TS-движок
(ГПСЧ на 7 сидах, распределение базы, разбор карты `aur_01`, ауры рун,
валидность шести колод). Переснять эталон после правок TS:

```bash
npx esbuild tools/csharp/rngref.ts --bundle --platform=node --outfile=/tmp/rngref.js \
  && node /tmp/rngref.js > tools/csharp/expected.json
```

`GameEngine.cs` не входит в сборку стенда, пока порт ядра не завершён: чтобы
включить его, создайте пустой файл-маркер `Assets/Scripts/Core/.engine-complete`
(условие `Condition="!Exists(...)"` в csproj). Так стенд остаётся зелёным,
а движок пишется частями.

Режим `-balance` (прогон N матчей на C# и сравнение винрейтов с
`docs/balance/faction_report.csv`, порог 2.5 п.п.) заработает после частей 2–3.

## ⚠ Критичная особенность ГПСЧ: `| 0` в конструкторе

`Rng` из `types.ts` — 32-битный xorshift, выход `((s0 + s1) >>> 0) / 2^32`.
Но в конструкторе TS умножает **в double**, а не через `Math.imul`:

```ts
this.s1 = (this.s0 * 1812433253 + 12345) | 0;
```

При `|seed| ≥ 11 930 465` произведение превышает 2^53, округляется, и результат
**отличается** от честного int32-умножения:

| seed | `s1` через double (как в TS) | `s1` через `Math.imul` / int32 |
| --- | --- | --- |
| 12345 | 2003875766 | 2003875766 (совпадает) |
| **20260903** | **2038883992** | 2038883996 (расхождение) |

Наш официальный seed баланса — `20260903`, то есть ровно «кривой» случай.
Поэтому C#-порт повторяет double-путь через `Rng.ToInt32Js()` (точная копия
JS-оператора `|0`: отбросить дробь → остаток по модулю 2^32 → знаковый int32).
Обычное `unchecked`-умножение `int` дало бы математически верный, но **другой**
результат и сломало бы воспроизводимость официальных прогонов баланса.

Проверено на сидах 1, 7, 42, 12345, 20260903, −987654321, 2147483647:
12 значений `next()`, `int()`, `range()` и порядок `shuffle()` совпадают побитово.

## Расхождения схемы данных, найденные при сверке

1. **Фракция `Neutral` существует** (6 карт `neu_01…neu_06`) — в перечислении C#
   она обязательна, иначе 6 карт не загрузятся.
2. **`Decks.json` содержит колоду `Starter` с `faction: "Starter"`** — значения нет
   в перечислении. Терпимый конвертер `LenientFactionConverter` приводит его к
   `Neutral`, и загрузка не падает. Конвертер обязан быть зарегистрирован **до**
   `JsonStringEnumConverter`, иначе System.Text.Json бросит исключение.
3. **Токены лежат отдельным массивом** `tokens` (7 шт.), а в эффектах карт
   `summonToken` объект токена встроен прямо в эффект (`eff.token`) — движок
   вызывает `summon(side, eff.token)`. Отдельный поиск по `tokens` не нужен,
   но массив используется для отображения и отладки.
4. **9 из 30 рун не имеют `aura`** — они работают через `effects`/`onTurnStart`.
   Аура с `op` есть у 21 руны, операций ауры 8.
5. **`spellDamageValue`, `heroProtection`, `spellDamage`, `aura.matches`** в текущей
   базе не заполнены, но TS-движок их читает защитно — в C#-моделях поля есть,
   чтобы будущие карты не потребовали правки парсера.
6. `PlayerStats` в C# повторяет `MatchStats` из `engine.ts` **поле в поле**
   (включая `ManaSpent` и `Losses`) — иначе отчёты баланса TS и C# несопоставимы.

## Что уже сверено (82 проверки, 0 провалов)

- ГПСЧ: 7 сидов × {12 значений `next()`, `int()`/`range()`, `shuffle()`};
  seed 0 не вырождается; `pround(1.4)` даёт матожидание 1.4 на 200 000 бросках.
- База: 156 карт + 7 токенов; распределение по типам (81/45/30), редкостям
  (96/38/15/7) и фракциям (30×5 + 6 нейтральных) — совпадает с TS.
- Разбор `aur_01`: имя, фракция, тип, редкость, стоимость, атака/здоровье,
  стихия, целеуказание, ключевые слова.
- Руны: ауры и `runeLimit` прочитаны, 21 аура, 8 операций.
- Эффекты: 23 операции распознаны, 8 эффектов `summonToken` со встроенными токенами.
- Колоды: 6 колод по 40 карт, все валидны; валидатор ловит превышение лимита копий.
- Коэффициенты: 5 фракций, `passiveMul` совпадает с `docs/balance/solver_result.json`
  (Ауриты 0.4744, Некрусы 1.4003, Терраморфы 1.3698, Пироманты 1.8235, Эфирные 0.5585).
